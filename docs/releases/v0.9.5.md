Cineol-X 224 v0.9.5 for **macOS Universal** and **Windows x64**.

This release includes the changes developed since the last published version,
v0.6.0: native 224 XL preview, a managed preset bank, a redesigned editor,
Spillover, eight quick preset keys and editor focus fixes.

### Algorithms and sound controls

- All 22 **224 XL v8.21** programs join the six original **224 v4.4** programs.
  The algorithm menu selects the engine automatically. XL exposes its own two
  to seven parameter pages, including decay, filters, depth/attack, pre-delay,
  Chorus, Diffusion, Definition, levels, delays, pan, feedback and Size where used.
- Each program chooses an appropriate output pair: A/C for regular reverbs,
  A/B for split programs and C/A for Chorus & Echo. Manual XL selection recalls
  its factory controls; original-224 controls, Input, Mix and Dirt are retained.
- Native XL processing uses graph-specific clocks, rational resampling and
  X/XL circuit profiles. Continuous Dirt blends the filtered and unfiltered
  paths. XL frequency and decay values without a finite upper bound show `INF`.
- XL dynamic decay/gating, Decay Optimization and associated stop controls
  remain disabled. This desktop preview does not claim complete hardware
  equivalence. Daisy continues to use the original-224 engine.

### Spillover

- Settings adds a **Spillover** checkbox and a **1–10 second** selector on the
  same row, defaulting to **off** and **5 seconds**. It works within 224,
  within XL and across 224 ↔ XL transitions, including quick-preset recalls.
- A new algorithm starts processing input while the previous engine retains
  its controls, memory and output routing and fades its remaining wet tail.
  A shared dry path avoids doubled or interrupted dry audio.
- Only one outgoing tail is retained. Rapid switching retires the oldest tail
  over 20 ms before reusing the engine. Processing is bounded to two engines;
  CPU demand temporarily increases while both run.
- Turning Spillover off fades an existing tail and restores hard switching
  for subsequent changes. Spillover and Low latency are instance settings saved
  in DAW sessions, independent of sound presets. Older sessions keep Spillover off.

### Presets and editor

- **Save preset** adds a named entry to one shared user bank. Reusing a name
  asks for replacement confirmation. Older `.cineol224` files in the default
  preset folder are adopted without deleting the originals.
- The themed browser supports alphabetical listing, search by preset/algorithm/
  model and multiple algorithm filters. Presets store firmware identity and
  all sound controls, including hidden pages. Failed or unavailable recalls
  preserve the current sound. Preset names and modified markers survive sessions.
- Eight numbered **Quick presets** keys sit above the lower mounting screws.
  Select a browser preset, choose **Assign to...**, then key 1–8. Assignment
  replaces that slot without loading sound; pressing the key recalls it.
  Assignments are per instance, persist in sessions and reference current named
  bank entries. Empty keys are disabled, and a red LED marks the recalled preset.
- Fader caps animate for 320 ms after preset recall without generating extra
  parameter events. Direct numbered page selection, scrolling long preset names,
  disabled parked faders and the permanent Dirt/Input/Mix columns improve navigation.
- The extended photographic metal faceplate and textured keyboard-style keys
  replace stretched lower-panel strips and enclosing key frames. Menus, settings
  and preset dialogs share a consistent metal/red-display theme.
- Popup menus and preset dialogs now belong to their editor. Hidden or unfocused
  editors cancel unfinished dialogs, and one instance's dialog cannot lock another
  instance's faders. Modal completion clears editor state synchronously, allowing
  Save to reopen even when the host delays cleanup. Closing one editor dismisses
  only its own menus. This addresses the blocking scenario reported in Logic Pro.

### Downloads and installation

**macOS Universal** contains AUv2, VST3 and Standalone for Apple Silicon and
Intel, targeting macOS 11 or later:

- Copy `AU/Cineol-X 224.component` to `~/Library/Audio/Plug-Ins/Components/`.
- Copy `VST3/Cineol-X 224.vst3` to `~/Library/Audio/Plug-Ins/VST3/`.
- Copy `Standalone/Cineol-X 224.app` to Applications if needed.

Bundles are ad-hoc signed without Developer ID notarization. See `INSTALL.txt`
for installation and quarantine handling.

**Windows x64** contains VST3 and Standalone. Copy the entire
`VST3/Cineol-X 224.vst3` folder to `C:\Program Files\Common Files\VST3\`.
The optional standalone application is `Standalone/Cineol-X 224.exe`.

Restart or rescan your DAW after replacing an installed version. Existing plugin
identifiers and parameter IDs remain stable. Sessions without quick-key metadata
restore eight empty assignments. The original-224 import cache remains compatible;
the XL preview requires its own supported cache/import.

The Program parameter now offers 28 algorithms, so its normalized automation
scale is expanded compared with the earlier six-program version.

### First launch: import your ROMs

The build is supplied without ROM files. Import them before using reverb:

| Programs | Model and firmware | Complete ROM set required |
| --- | --- | --- |
| Six original programs | **Lexicon 224 v4.4** | **ROM1–ROM5**, five 2,048-byte files |
| 22 desktop XL programs | **Lexicon 224 XL v8.21** | Eleven chip files of 2,048 or 4,096 bytes |

1. Open Cineol-X 224 in your DAW or launch the standalone application.
2. Click **Choose ROMs...** in the first-use panel. Select the folder, ZIP or
   complete ROM files for the supported version you want to import.
3. Wait for local preparation to finish, then select an enabled algorithm.
4. To add the other model, click the **Model / 224 / 224 XL** indicator on the
   red display and import its separate complete ROM set.

Both sets are needed for all 28 algorithms. A 224 v4.4 set does not enable XL
programs, and an XL v8.21 set does not enable original-224 programs. Filenames
are unimportant: the importer identifies chips by SHA-256. **224X v8.1**,
**224 XL v8.1A**, other versions, incomplete and modified sets are rejected.
Until a required bank is ready, reverb is unavailable and audio passes dry.
After import, later launches use the local cache without selecting ROMs again.
Your files stay on your computer.

### ROMs and validation

Supply your own original **224 v4.4 ROM1–ROM5** set for original-224 programs.
The optional desktop XL preview requires its own complete supported **224 XL
v8.21** ROM set. No ROMs, prepared banks, captures or Daisy firmware are shipped.
Private fixtures remain local and are never uploaded to GitHub Actions.

Both platform jobs build and package their binaries and run empty-cache first-use
checks. Packaging verifies macOS universal architectures and strict signatures
before and after ZIP extraction, Windows x64 PE binaries and archive integrity.

Local macOS checks with private banks passed all 28 programs at 44.1/48/96 kHz,
575 active fader endpoints, preset/state compatibility, quick-key assignment,
Spillover reference comparisons for 1/5/10 seconds, rapid switching, dry continuity,
block-size invariance and zero audio-callback allocations/releases. A two-window
GUI regression passed hidden-dialog cancellation, reopening, instance isolation
and fader dragging after preset recall. Installed AU validation passed.

The Logic-specific report was checked with simulated host windows; direct retesting
inside Logic Pro was unavailable because the local Mac was locked. CI does not
perform imported-bank DSP validation on Windows. These checks do not establish
realtime CPU margin or replace listening tests.

`SHA256SUMS.txt` covers both platform ZIPs. Each archive includes installation
instructions and `BUILD-INFO.json` with the source commit and dependency pins.
