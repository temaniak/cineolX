Cineol-X 224 v0.9.8 for **macOS Universal** and **Windows x64**.

### Sound refinements

- Refined the original **224 v4.4** input/output conversion, control-write
  timing at DSP fetch boundaries, and modulation startup/counter retention.
- Refined **224XL v8.21** input/output circuit processing, channel capture/write
  timing and modulation initialization. These corrections target frequency
  balance, decay behavior and response to controls without compensating EQ.
- Retained the abrupt, sometimes stepped short-tail ending in Dynamic Decay
  observed in the ROM-based reference. No additional tail smoothing is applied.
- Faster offline ROM preparation; the realtime audio path remains native C++.

### Editor

- Bottom controller captions and values and right-hand Left/Right, Model,
  Dynamic Decay, Mod Enhancement and Decay Optimization fields now share one
  fixed LED font size. Long captions are abbreviated instead of being shrunk
  individually, for example **HF BANDWIDTH** becomes **HF BW**.
- Full fader names/tooltips and automation metadata remain available. Channel
  suffixes, route identifiers, control values and their units are preserved.
- The editor opens at **984 x 744**, its existing minimum size. Resizing remains
  available; a host may restore a previously saved window size.

### Compatibility and upgrade

Plugin identifiers, existing parameter IDs/indices and sound-preset/session
formats remain stable. Both engines are included: six original-224 programs
and the 22-program desktop XL preview, with the shared preset bank, eight quick
preset keys, Spillover, continuous Dirt and Low latency.

**XL now requires the corrected version-5 prepared cache. Re-import your complete
original 224XL v8.21 ROM set once when upgrading from an older cache, including
v0.9.6's version-4 cache.** Click the Model / 224 XL indicator to open ROM setup.
Previous XL caches, the original-224 cache and existing presets are retained.
If the corrected v5 cache has already been prepared locally, no further import
is required. ROM import fixes from the 0.9.6 Fixed rebuild remain included.

### Downloads and installation

- **macOS Universal:** AUv2, VST3 and Standalone, Apple Silicon and Intel,
  macOS 11 or later. Copy AU to `~/Library/Audio/Plug-Ins/Components/`, VST3 to
  `~/Library/Audio/Plug-Ins/VST3/`, and the standalone app to Applications.
  Bundles are ad-hoc signed, not notarized; see `INSTALL.txt` for installation.
- **Windows x64:** VST3 and Standalone. Copy the entire `.vst3` folder to
  `C:\Program Files\Common Files\VST3\`. The standalone executable is optional.

Restart or rescan your DAW after installing. `SHA256SUMS.txt` covers both ZIPs;
each contains installation instructions, release notes, README and build/source
provenance in `BUILD-INFO.json`.

ROMs, prepared banks and private recordings are not included. Supply your own
original **224 v4.4 ROM1-ROM5** (five 2,048-byte files) for the six 224 programs,
and the complete **224XL v8.21** eleven-chip set (SBC1-SBC3, three 2,048-byte
files; NVS1-NVS8, eight 4,096-byte files) for XL. Both sets are needed for all
28 programs. Incomplete, modified and unsupported firmware sets are rejected.
Before preparation, unavailable engines remain disabled and audio passes dry.

### Validation and current limits

Local private-ROM checks and the full dual-bank plugin regression pass all
28 programs, 618 active fader endpoints, presets/session restoration, page
navigation, mono/stereo, Spillover and block-size independence at 44.1/48/96 kHz.
Audio callback allocation/release counts remain zero. The installed local AU
passes strict system `auval` validation. Expanded isolated macOS focus checks
pass cross-window focus, dialog/menu ownership and rapid hide/reopen cycles.

Both release platforms build and check empty-cache first use and invalid-ROM
import without private firmware. Packaging checks macOS universal architectures
and signatures, Windows x64 PE binaries, ZIP integrity and SHA-256 checksums.

XL remains a preview. Measurements cover the catalog; eight distinct musical
algorithms have positive user listening feedback, while the remaining fourteen
musical examples await listening review. Checks use the ROM-based software
reference and do not establish complete equivalence to a physical unit.
An intermittent Logic issue where controls stop responding after returning
from another window is not reproduced by the isolated tests and is **not claimed
fixed**. Full native OS first-click behavior in that Logic scenario still needs
host verification. Daisy hardware behavior and realtime margin are outside this
desktop release validation.
