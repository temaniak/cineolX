Cineol-X 224 **1.1a** for **Windows x64** and **macOS Universal**.
This is a GitHub **prerelease**, with numeric plugin/bundle version **1.1.0**.
Changes below are relative to 1.0Alpha. Manufacturer remains **NK Stuff**;
existing plugin identifiers and host parameter IDs/indices are retained.

### Clean on all 28 algorithms

- **Settings → Clean** enables the accepted higher-precision fixed-point path
  on all six original-224 and all 22 XL programs, including effects and splits.
  It reduces quantization noise while retaining the original delay networks,
  coefficient quantization, nominal clocks, modulation and converter filters.
- Clean selects restored panel, bezel, fader and quick-key textures. The same
  control geometry and full/compact layouts are used in both skins.
- **Dirt remains independent**: it still changes converter-filter bandwidth.
  Clean does not automatically brighten or bypass the filters.
- Both precision histories stay active; a short crossfade retains a ringing
  tail when Clean changes. This increases CPU and memory use even with Clean
  off. A Spillover transition can add a second active program slot.

### Dark Hall variation

- **Dark Hall → page 5 → third fader: Variation** is an ordinary one of the
  six page faders. Its screen value reads **Stable** at 0, **Original** at 1,
  and a percentage between. Compact mode uses the same draggable screen value.
  Double-click restores Original.
- Stable reduces excessive internal LF/Mid feedback at long decay settings;
  Original bypasses this correction and preserves v8.21 self-oscillation where
  it occurs. The variation works in both precision modes.
- Both ends retain the v8.21 graph. **Stable is not v8.1/v8.1A firmware
  emulation**, and no support for those ROM sets is added. Lower feedback
  changes the long-lived modes and tail duration. Finite stability tests do
  not prove stability for every possible setting or automation trajectory.

### Original 224 and XL controls

- Original-224 page 3 adds **Mod Rate**, **Mod Depth** and **Opt Resp**, all
  on the hardware's unitless 1–16 scales. Rate/Depth interaction, factory reset,
  automation, and preset/session recall follow the verified control behavior.
- Restored XL controls include Chorus/Echo voice levels, Resonant Chords
  pitches, Multiband Delay times, Inverse Room Mid decay and CD Plate LF decay.
- Restored **Chorus** and Mode Enhancement availability in **Rich Plate** and
  **Rich Split**. Their native controller now models progressive LF/Mid decay
  and Optimization updates with coupled work timing. This corrects large
  input/mode-dependent timing errors without inventing additional delay-tap
  modulation or claiming complete hardware timing equivalence.
- Corrected HF frequency endpoints: the editor stops at the valid 254 value;
  old 255 automation/preset values resolve to it. This fixes signal loss at
  affected Treble/HF Bandwidth maxima while preserving the host parameter IDs.

### Host and editor fixes

- Host bypass uses the correct compensated dry delay, smooth transitions and
  retained DSP/tail histories. Mono input is correctly duplicated to Front;
  Rear fades to silence. Low latency keeps its direct dry path. DSP continues
  running during bypass; hosts that suspend processing can behave differently.
- Active page parameters now fill the six fader columns from left to right.
  Physical faders, screen values, captions, help and automation share the order.
- **Windows:** improved fader-cap and quick-key minification using Direct2D
  high-quality cubic filtering, including fractional display scales and both
  skins. Source artwork and control hit areas are unchanged.
- **macOS AU:** a bounded idle-paint workaround addresses reported loss of
  mouse input in Logic remote views. It remains an experimental workaround,
  not a claim that every Logic first-open/focus issue is resolved.

### Compatibility and installation

- Clean defaults **off**, Variation defaults **Original**. Old presets/sessions
  restore these defaults and original-224 advanced defaults 2/1/5. Preset schema
  **7** reads schemas **1–6**; new presets need this or a later compatible build.
- Corrected formerly inactive XL controls, HF endpoints and Rich timing can
  change affected old sounds. Keep previous binaries/session copies when an
  exact historical render is required.
- Existing original-224 and corrected **XL v5** caches are reused; no new cache
  migration is introduced. Re-import the complete XL v8.21 set only if upgrading
  from an older XL cache. Previous caches and user presets are retained.
- **Windows x64:** VST3 and Standalone. Install the complete `.vst3` folder in
  `C:\Program Files\Common Files\VST3\`.
- **macOS Universal:** AUv2, VST3 and Standalone for Apple Silicon and Intel,
  macOS 11 or later. Bundles are **ad-hoc signed and not notarized**; see
  `INSTALL.txt` for installation and downloaded-bundle quarantine handling.
- Restart/rescan the host after replacing the plugin. Logic AU effect slots
  remain stereo; optional Rear outputs require a host supporting extra effect
  outputs. SPACE, Dirt and existing output routing are retained.
- Supply your own original **224 v4.4** and optional complete **224XL v8.21**
  ROM sets. ROMs, prepared banks, firmware images and private recordings are
  excluded from the downloads.

### Validation and limits

The assembled DSP passed local all-program checks at 44.1/48/96 kHz, four-output
precision comparisons, retained-tail switching, Spillover, dry-path checks,
preset/session migration and callback allocation checks. Stable passed 144
finite 45-second long-tail fixtures in both precision modes. The installed
arm64 trial AU passed system validation. New all-program/Stable listening
acceptance remains separate from the user's accepted seven-program Clean trial.

Windows x64 and macOS Universal release CI builds both formats, runs the public
Space-clock and isolated empty-cache/import/UI checks, and verifies archive
contents, architectures, checksums and macOS bundle signatures. Windows CI also
produces 16 native Direct2D snapshots for both skins at 100/125/150/200% pixel
scales and two editor widths. These offscreen renders do not establish
compatibility with every DAW, GPU or physical monitor configuration. Intel
build/signature verification does not by itself establish Intel runtime or
listening acceptance. Desktop results do not establish Daisy realtime margin.
