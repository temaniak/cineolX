Cineol-X 224 v0.6.0 for **macOS Universal** and **Windows x64**.

### What's new

- A gear button in the top-right corner opens **Settings**. The panel reserves space for future fine tuning.
- **Low latency** sends the dry signal directly at the project sample rate and reports **0 samples** of plugin latency. It works at 44.1, 48 and 96 kHz, including mono input.
- The reverb still passes through its original filters and resamplers; its filter delay and pre-delay remain. The timing between dry and wet changes. At 100% wet, the DSP output is unchanged, but the DAW no longer compensates its delay.
- The setting is saved per plugin instance and defaults to **off**, including in older sessions. Existing plugin identifiers, parameter IDs and parameter indices are preserved. Low latency is not automatable; some hosts need a transport restart after changing compensation.
- Automatic GitHub Actions builds now produce both platforms. A version tag publishes both archives and their SHA-256 checksums after the builds pass. Manual runs create downloadable build artifacts; an optional **publish** checkbox on `main` also creates the version tag and release after both builds pass.

### Downloads and installation

**macOS Universal** includes AUv2, VST3 and Standalone for Apple Silicon and Intel, targeting macOS 11 or later. Extract the ZIP and copy the desired bundles:

- `AU/Cineol-X 224.component` to `~/Library/Audio/Plug-Ins/Components/`
- `VST3/Cineol-X 224.vst3` to `~/Library/Audio/Plug-Ins/VST3/`
- `Standalone/Cineol-X 224.app` to Applications.

macOS bundles are ad-hoc signed without Developer ID notarization. The included `INSTALL.txt` explains installation and quarantine handling.

**Windows x64** includes VST3 and Standalone. Extract the ZIP and copy the complete `VST3/Cineol-X 224.vst3` folder to `C:\Program Files\Common Files\VST3\`. The optional standalone application is in `Standalone`.

Restart or rescan your DAW. To enable the new mode, open the gear and check **Low latency**. Audio-interface and host-buffer latency remain independent of this setting.

### ROMs and compatibility

Supply your own five original **Lexicon 224 v4.4 ROM1-ROM5** files on first use. Import is local. ROMs, prepared banks and firmware are not included in either archive. 224X and 224XL ROMs are not supported. Existing ROM caches remain compatible.

### Validation

Both build jobs run first-use checks with an empty cache, including Settings, saved Low latency state, reported latency at 44.1/48/96 kHz, mono/stereo dry pass-through and allocation-free audio processing before ROM import. macOS packaging verifies arm64/x86_64 architectures and strict code signatures, including after ZIP extraction; Windows packaging verifies x64 PE binaries.

Local macOS checks with a private supported bank also verified all six algorithms, exact unchanged 100% wet output, zero-delay dry input, host-rate dry/wet mixing, different block sizes, offline/realtime equivalence, state compatibility and zero callback allocations/releases. Those private fixtures are not uploaded to CI. Full DSP execution on Windows and physical Intel Macs is not claimed by these checks.

`SHA256SUMS.txt` covers both ZIP files. Each archive includes `BUILD-INFO.json` with its source commit and dependency pins.
