# Clean A/B fixed-point prototype — 2026-11-02

Subsequent implementation: the accepted precision method is now available in
the main plugin for all 28 algorithms, with the independent Dark Hall variation
and clean skin. See [global Clean rollout](CLEAN_ALL_ALGORITHMS_2026-11-02.md).
The text below records the separate prototype and its original validation.

## Delivery and scope

The user approved the seven-program shortlist on November 2. A separate **Cineol Clean AB** AU/VST3/Standalone prototype is implemented. It has distinct identifiers (`net.nkstuff.cineolcleanab`, AU `aufx/CcAB/Rflx`). The ordinary Cineol-X 224 DSP, parameters, imported caches and installed plugin are not replaced. No public release or tag is created.

The prototype contains the three approved original-224 programs and four XL programs listed below. The existing 48 kHz Float Hall is not used.

## Signal change

A runs the current production native engine. B runs namespace-isolated copies of the same local core/desktop sources with a 28-bit fixed-point signal word (16 original bits plus 12 fractional bits), held in signed 64-bit containers. The original ARU sequence, coefficient quantization, word wrapping, scaled accumulator limits, delay addresses, graph clocks and controller scheduling remain. Finer input conversion retains converter scaling and range thresholds; B omits the original output DAC truncation. The continuous-time converter-filter models and event timestamps remain unchanged. There is no gate, denoiser, widening EQ or new interpolation/host-rate algorithm.

Prepared bank layouts are unchanged and checked before a trivially-copyable, off-audio-thread copy into the isolated namespace. Controls observe original-sized words reduced from the extended audio signal. Near a level boundary this can change controller decisions because the audio/converter precision changed; exact nonlinear/controller equality is not claimed. Existing control steps and overload behavior are retained, rather than redesigned.

The export is generated by `native-hall/clean-ab/generate_precision.py` in the build folder. Critical source boundaries have checked substitutions and a complete source hash manifest. The default build option is OFF. Two added root CMake entries wire the independent folder; existing production processing source is not edited by this experiment.

## Narrow before/after evidence

All seven programs use wet A/C output, 48 kHz, nominal native clocks and converter filters, Dirt/Space zero, one-second silent warmup and unchanged control recipes. The noise-floor screen uses 0.5 seconds of independent stereo uniform noise followed by 30 seconds of silence. Cases are seed17/peak0.08 and seed991/peak0.008, each with Mod+Optimization off and on. Dynamic Decay is off. Original faders use common plugin defaults, hidden rate2/depth1/optimization5 and minimum predelay; XL faders use factory values. These cases do not exhaust settings, nonlinear levels or controller phases.

The final 28–30-second AC RMS subtracts each channel mean before pooling channel powers. The table shows the highest residual of four cases separately for A and B; the maxima may come from different cases. -360 dBFS is the numeric reporting floor, not a measured specification. In cases where A already reaches numerical silence, B can retain an extremely small residual instead; cleanup is not monotonic in every numerical case.

The independent character fixture drives four seconds of stereo noise at peak0.08 with Mod/Opt off and records ten seconds of silence. Welch analysis of active seconds2–4 uses the same 4096-point Hann windows on A and B. All seven programs' active 100 Hz–8 kHz band differences are below 0.0011 dB. For frequency-dependent decay, each pair uses the same original-selected -5 to -25 dB window set; all 49 paired band fits have R² at least0.95, with absolute T60 deviation below0.2%. This establishes close band/envelope behavior for these settings, not sample equality or listening acceptance.

Private metrics and reproduction sources are under `build/validation/clean-ab-20261102/`: `metrics.csv`, `character.json`, `character.cpp`, `analyze_character.py`, core/plugin/sanitizer logs and CPU CSV. No user audio, ROMs or banks are deleted.

## Validation

- Zero-extra-bit export: all seven programs × four recipes match A exactly, maximum sample difference0. This guards isolation and graph/converter transfer.
- Actual extra12-bit path: all28 recipes finite and bounded; selection/process C++ allocation count0. The largest A/B sample difference in that bounded test is0.0003658822.
- AddressSanitizer and UndefinedBehaviorSanitizer core checks pass for all seven programs/four short recipes; not an exhaustive extreme-control proof.
- Actual processor: seven A/B routes match independent engine instances; A/B switching during input silence preserves both histories through the 10 ms crossfade.
- Host bridge: 44.1/48/96 kHz; blocks1/128/511; rapid algorithm changes; finite output. Mono-to-stereo and exact 70-frame dry alignment at48 kHz pass. Parameter/state roundtrip and UI creation for all seven pass. Callback allocation count0.
- AU, VST3 and Standalone built on macOS arm64 with pinned JUCE8.0.14. Ad-hoc code signatures verify. The separately installed AU passes Apple auval. Windows and Daisy execution are not validated.
- Offline JUCE component snapshots for all seven programs were generated and visually reviewed for the original and XL page layouts. Standalone launch via Launch Services succeeds. The computer-use service timed out, so no live interactive-window inspection or actual audio listening is claimed.

The first system AU validation ran before discovery of the newly installed component and reported not found. A subsequent targeted validation succeeds. An optional full inventory was stopped when it stalled loading unrelated installed plugins. No existing DAW or main plugin was stopped.

## Listening handoff

Use **Cineol Clean AB** in the DAW, or launch its separate application. Start at100% wet, select an algorithm, and match active loudness with B Level Trim before comparing quiet tails. Wet B RMS includes that trim. Output gain is common to the final mix. Original and XL controls are shared between A and B; algorithm changes reset both branches. A/B changes retain both tails.

The user subsequently reported a successful listening test and accepted the noise reduction in this prototype. This is acceptance of the tried material/settings, not an exhaustive sonic or stability certification. They requested eventual extension to all algorithms, but first reported Dark Hall self-excitation in both branches at long LF/Mid decay and elevated Treble Decay. The [Dark Hall investigation](DARK_HALL_RUNAWAY_2026-11-02.md) records original-hardware evidence, an independent v8.21 firmware reproduction, and a Clean-specific stability-boundary qualification. Further rollout and any stability correction remain separate work.
